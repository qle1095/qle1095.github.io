# Interactive Resume — "The Journey"

A scrollytelling resume website: the visitor scrolls, and a chibi 3D version of you
walks left-to-right through your career timeline — passing milestones, collecting
skills, and moving through visually distinct "eras" of your journey.

---

## 1. Concept & Experience Design

### Core mechanic
- The page scrolls **vertically** (natural mouse wheel / touch), but the stage is
  **pinned** and the world translates **horizontally** — a side-scroller.
- The chibi character stays anchored at ~35% from the left edge, walking in place
  while the world moves past. Walk animation speed follows scroll velocity;
  the character goes **idle** (blinking, breathing) when scrolling stops.

### The world
- **Chapters (eras):** each major phase of your career (education, job 1, job 2, …)
  is a chapter with its own background palette/scenery, so progress *feels* like travel.
- **Milestones:** signposts/stations along the path — role, company, dates, 2–3 line
  story. Cards animate in as the character reaches them; character plays a short
  **celebrate** animation at major ones (promotion, launch, degree).
- **Skills as pickups:** floating badges (React logo, Python, AWS, …) hovering on the
  path. As the character passes, the badge flies into a persistent **skill inventory
  HUD** at the screen edge — by the end, the HUD is your full skill list.
- **Progress bar:** top of screen, labeled with years (e.g. 2016 ──── 2026),
  doubling as chapter navigation (click a year to jump).

### Opening & ending
- **Intro:** hero screen with name, title, "Scroll to begin the journey ↓".
  (Optional: short autoplay-muted video loop here for cinematic first impression —
  this is where video belongs, not scroll-scrubbed.)
- **Outro:** character arrives at "today" — current role summary, contact links,
  **Download PDF resume** button, GitHub/LinkedIn.

### Accessibility & fallbacks
- All milestone/skill text is real HTML → SEO-visible, selectable, screen-reader friendly.
- `prefers-reduced-motion`: disable character/parallax animation, present the same
  content as a clean static vertical timeline.
- No-WebGL fallback: hide the canvas, keep the world (site still fully works).

## 2. Architecture

| Layer | Tech | Role |
|---|---|---|
| App | Vite + React + TypeScript | Structure, components, data-driven rendering |
| Scroll engine | GSAP ScrollTrigger (+ Lenis smooth scroll) | One master scrubbed timeline drives everything |
| World | DOM/CSS/SVG parallax layers | Scenery, milestone cards, skill badges — cheap, authorable, accessible |
| Character | React Three Fiber + drei, transparent canvas | Chibi model generated by **img2threejs**, pinned overlay |
| Data | `src/data/journey.ts` | Single source of truth: chapters, milestones, skills, positions |
| Deploy | Vercel (or GitHub Pages) | Free hosting, instant deploys |

### Key design decisions
1. **Hybrid rendering** — DOM world + WebGL character. Full-3D worlds make text
   authoring, SEO, and mobile perf much harder for little gain. The character is the
   only thing that truly benefits from 3D.
2. **Data-driven timeline** — updating your resume = editing `journey.ts`. No layout
   or animation code touched.
3. **One master timeline** — a single `ScrollTrigger` with `scrub` maps scroll
   progress 0→1 to world position; every animation (card reveals, pickups,
   era color shifts, character states) keys off it. Deterministic and easy to tune.
4. **Character as a swappable slot** — the character component exposes
   `{ state: 'idle' | 'walk' | 'celebrate', velocity }`. If the 3D likeness
   disappoints, a 2D sprite implementation drops into the same interface.

### Data model sketch
```ts
type Skill = { id: string; label: string; icon: string };
type Milestone = {
  id: string;
  date: string;            // "2019-06"
  title: string;           // "Senior Engineer @ Acme"
  story: string;           // 2–3 lines, first person
  kind: 'job' | 'education' | 'achievement' | 'launch';
  celebrate?: boolean;     // triggers character celebration
  skills?: Skill[];        // pickups placed just before this milestone
};
type Chapter = {
  id: string;
  label: string;           // "The University Years"
  theme: { bg: string; accent: string };  // era palette
  milestones: Milestone[];
};
```
Horizontal positions are computed from chronology (proportional to time, with a
minimum gap), so you never hand-place anything.

## 3. Implementation Phases

### Phase 0 — Inputs (you)
- [ ] Resume content: jobs, dates, milestones, skills (any format — I'll structure it)
- [ ] A clear reference photo of yourself for the chibi generation
- [ ] Install the img2threejs skill: clone https://github.com/img2threejs/img2threejs
      into `~/.claude/skills/` (I can run this)
- [ ] Decide domain/hosting preference (default: Vercel free tier)

### Phase 1 — Scaffold (small)
- Vite + React + TS project, GSAP, @react-three/fiber, @react-three/drei, Lenis
- Git repo init, ESLint/Prettier, deploy pipeline wired early (empty site on Vercel)

### Phase 2 — Scroll engine (core, do first)
- Pinned full-viewport stage; scroll height proportional to journey length
- Master ScrollTrigger timeline → horizontal world translation
- Progress bar with year markers + click-to-jump
- **Placeholder box as character** — proves the whole mechanic before any art exists
- ✅ Checkpoint: scrolling smoothly drives a box through an empty world

### Phase 3 — Data & content (medium)
- `journey.ts` populated from your real resume
- Chapter sections, milestone cards, skill badges rendered from data
- Card reveal animations, skill "fly to HUD" pickup animation, era color transitions
- ✅ Checkpoint: full real-content journey works end-to-end with placeholder character

### Phase 4 — The chibi character (medium-high, riskiest — isolated on purpose)
- Run img2threejs on your photo → procedural Three.js chibi (iterate on likeness)
- Mount in transparent R3F canvas over the world
- Rig walk cycle (limb rotation on the model's hierarchy), idle, celebrate
- Bind walk speed to scroll velocity; flip facing on reverse scroll
- Fallback: 2D sprite implementing the same character interface
- ✅ Checkpoint: chibi-you walks the journey

### Phase 5 — World art & polish (medium)
- Parallax layers (sky / far / mid / ground) per era
- Scenery motifs per chapter (campus, office, cloud/server props — matched to your story)
- Intro hero + outro contact scene, PDF resume link
- Micro-delights: footstep dust, milestone confetti on celebrate

### Phase 6 — Mobile, a11y, perf (small-medium)
- Touch scroll tuning; simplified parallax on small screens
- `prefers-reduced-motion` static timeline; no-WebGL fallback
- Lighthouse pass: transform-only animation, lazy layers, target 60fps / LCP < 2.5s

### Phase 7 — Ship
- Meta/OG tags (link preview card for recruiters), favicon, analytics (optional)
- Deploy to Vercel, custom domain if desired

## 4. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Chibi likeness takes many iterations | Isolated in Phase 4; site fully works with placeholder; 2D sprite fallback behind same interface |
| Scroll jank on low-end/mobile | Transform-only animations, DOM world (no full-3D scene), reduced layers on mobile |
| iOS Safari quirks (pinning, canvas) | Lenis + ScrollTrigger is the battle-tested combo; test early on real device |
| Resume updates becoming painful | Everything data-driven from `journey.ts` |
